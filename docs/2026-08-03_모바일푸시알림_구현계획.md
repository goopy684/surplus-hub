# 모바일 푸시 알림 — 구현 계획

작성일: 2026-08-03

## 1. 현황 진단

### 이미 있는 것 (백엔드)
| 항목 | 위치 |
|---|---|
| `Notification` / `DeviceToken` 모델 | `app/models/notification.py` |
| CRUD (목록·읽음·미읽음·토큰 등록/해제) | `app/crud/crud_notification.py` |
| REST 엔드포인트 6개 | `app/api/endpoints/notifications.py` |
| FCM 발송기 (미설정 시 no-op) | `app/core/push.py` |
| 인앱 알림 목록 화면 (웹·모바일) | `apps/web/src/app/notifications/page.tsx`, `apps/mobile/app/notifications.tsx` |
| 알림 API 클라이언트 | `packages/core/src/api/notifications.ts` |

### 빠진 것 — 이게 이번 작업 범위
1. **Expo push 전송 경로 없음.** 모바일이 Expo(SDK 57 / EAS)인데 `push.py`는 원시 FCM 토큰만 처리한다. `ExponentPushToken[...]`을 보내면 실패한다. → 서버 자격증명 없이 동작하는 Expo Push Service 경로를 추가해야 실제로 알림이 도착한다.
2. **모바일에 `expo-notifications` 자체가 미설치.** 권한 요청·토큰 발급·수신 핸들러·탭 시 딥링크·배지 전부 없음. 즉 지금은 푸시를 **받을 수단이 없다.**
3. **알림 수신 설정 없음.** 사용자가 끌 수 없다. 광고성 알림은 정보통신망법상 옵트인이 필수.
4. **트리거가 채팅뿐.** 그 채팅 코드조차 3곳에 복붙되어 있다 (`ws.py` 2곳, `chats.py` 1곳).
5. **무효 토큰 정리 없음.** 앱 삭제/토큰 만료된 기기로 계속 발송 시도.
6. **관리자 발송 수단 없음.** 공지·이벤트 푸시를 보낼 방법이 전무.

## 2. 설계 결정

### 결정 1 — 전송은 Expo Push 우선, FCM 병행
Expo Push Service(`exp.host`)는 서버 측 자격증명이 필요 없고 APNs/FCM을 대신 처리한다. `send_push_notification()`이 토큰 모양으로 분기한다:
- `ExponentPushToken[...]` → Expo (100개 단위 청크)
- 그 외 → 기존 FCM 경로

FCM 서비스 계정 파일 없이도 모바일 푸시가 끝에서 끝까지 동작한다. 기존 FCM 코드는 버리지 않는다.

### 결정 2 — 수신 설정은 `users` 테이블의 불리언 5개 (별도 테이블 X)
`push_enabled`, `push_chat`, `push_material`, `push_community`, `push_marketing`.
별도 테이블 대비: 조인 없음, JSON 파싱 없음, 관리자 타겟팅 쿼리(`push_marketing=true`)가 그대로 SQL. `push_marketing`만 기본 **false** (정보통신망법 옵트인).

### 결정 3 — 발송 지점을 `notify()` 하나로 통합
현재 3곳에 복붙된 "토큰 조회 → 푸시 → 알림 행 생성"을 `app/core/notify.py`의 `notify()` 한 곳으로 모은다. 새 트리거는 한 줄 호출로 붙는다. 근본 수정이 곧 최소 diff.

```
notify(db, *, user_id, type, title, body, reference_type=None,
       reference_id=None, data=None, push=True) -> Notification | None
notify_many(db, *, user_ids, ...) -> {targeted, created, pushed, failed, skipped}
```
동작: 인앱 알림 행은 **항상** 생성 → 수신설정 통과 시 활성 토큰으로 푸시 → 응답의 무효 토큰 자동 비활성화 → 전 구간 try/except (알림 실패가 본 요청을 깨뜨리지 않는다).

### 결정 4 — 웹 푸시는 범위 외
`apps/web/src/app/sw-unregister.tsx`가 서비스워커를 의도적으로 해제하고 있다. 목표도 "모바일 푸시"다. 웹은 인앱 알림 목록(기존) + 관리자 발송 콘솔만.

## 5. 검증 기준
- `python -m pytest app/tests -q` — 신규 통과, 기존 회귀 없음(변경 전 기준선과 대조)
- `packages/core`, `apps/web`: `npm run lint` · `npm run check-types` 클린
- `apps/web`: `npx jest` — 기존에 실패하던 스위트 외 회귀 없음
- 실기기 발송은 EAS 빌드가 필요하므로 코드 경로는 목(mock) 테스트로 검증하고, 실기기 절차는 보고서에 남긴다.
