## 0. 최종 아키텍처 (검증됨)

```
사용자 → Vercel(프론트, Next.js 모노레포 apps/web)
         → Railway(백엔드 FastAPI + Postgres 16 + pgvector 0.8.5)
         → Cloudflare R2(파일, S3 호환, presigned PUT)
         → Google OAuth(ID token) / Google Vertex AI(임베딩·생성)
```

| 요소 | 서비스 | 배포 방식 | 브랜치 |
|---|---|---|---|
| 프론트 | Vercel | GitHub 연결 자동배포 | `develop` |
| 백엔드+DB | Railway (Dockerfile) | GitHub 연결 자동배포 | `develop` |
| 파일 | Cloudflare R2 | S3 API (boto3) | - |

**실 배포 URL(prod)**: 프론트 `https://surplus-hub-react-web.vercel.app` / 백엔드 `https://surplus-hub-api-v3-production.up.railway.app`

## 1. 사전 준비 (계정·토큰·CLI)

### 1.1 필요한 계정/결제수단
- GitHub (repo 소유), Railway(카드 필요, 무료 영구 없음·Hobby $5/월), Vercel(무료), Cloudflare(R2, 카드 필요·무료 10GB), Google Cloud(OAuth+Vertex)

### 1.2 로컬 CLI
```bash
npm i -g @railway/cli wrangler   # vercel은 npx로 사용
# 검증: railway --version / wrangler --version / npx vercel@latest --version / docker / jq / openssl / python3(+boto3,psycopg2)
```
> ⚠️ 이번 환경에서 `vercel` 명령이 플러그인 shim이었음 → **반드시 `npx vercel@latest` 사용**.

### 1.3 발급할 값 (자세한 화면 절차는 v1 따라하기 가이드 참조)
- **Railway**: `railway.com/account/tokens` → **Account 토큰** (프로젝트 토큰 아님!). CLI에선 `RAILWAY_API_TOKEN`으로 사용.
- **Vercel**: `vercel.com/account/tokens`
- **Cloudflare 계정 API 토큰**: `dash.cloudflare.com/profile/api-tokens` → Custom → `Workers R2 Storage: Edit` (버킷/CORS 관리용, wrangler `CLOUDFLARE_API_TOKEN`)
- **R2 S3 자격증명**: R2 → Manage R2 API Tokens → Object Read & Write → **Access Key ID + Secret Access Key + S3 endpoint** (앱의 `AWS_*`)
- **Google OAuth Client ID**: console.cloud.google.com → Credentials → Web application. Authorized JS origins에 배포 도메인 + `http://localhost:4000` (와일드카드 불가, 정확 URL)
- **GCP 서비스 계정 JSON**: Vertex용. 로컬 파일(`owner/service-account.json`) 내용을 `GCP_SA_JSON`으로.

## 2. 함정 & 해결 (v2의 핵심 — 실제로 다 겪음)

| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| F1 | `railway whoami` → Unauthorized | 프로젝트 토큰 사용 | **Account 토큰**을 `RAILWAY_API_TOKEN`으로 export (`RAILWAY_TOKEN` 아님) |
| F2 | 첫 배포 crash: `could not translate host name "db"` | env 미설정, `POSTGRES_SERVER` 기본값 `db` | `DATABASE_URL=${{Postgres.DATABASE_URL}}` + 나머지 env 주입 |
| F3 | 2차 배포 crash: `mkdir: /etc/secrets: Permission denied` | 컨테이너 **비-root** 유저가 `/etc/secrets` 못 씀 (docker-entrypoint의 GCP SA 단계, `set -e`로 즉사) | 엔트리포인트에서 GCP SA를 **`/tmp/gcp.json`** 에 기록하도록 수정 (이미 반영됨) |
| F4 | `Healthcheck failed!` (30s) | 마이그레이션+웜업이 30초 초과 | `railway.json` `healthcheckTimeout: 300` (이미 반영됨) |
| F5 | 404 "Application not found" | 뒤에 살아있는 배포 없음(위 crash들) | crash 원인 해결 후 자동 회복 |
| F6 | R2 `NoSuchBucket` | 대시보드에서 만든 버킷명 불일치(`surplus-upload`) | 앱 설정과 일치하는 **`surplus-hub-uploads`** 생성 |
| F7 | R2 `SignatureDoesNotMatch` | S3 시크릿 오복사 | 새 R2 API 토큰 재발급, 정확 복사 (checksum 이슈 **아님** — default config로도 동작) |
| F8 | CORS 헤더 없음(GET) | 재배포 초기화 중 이전 컨테이너 응답 + **Starlette는 와일드카드 origin 매칭 안 함** | 재배포 완료 대기 + `CORS_ORIGINS`에 **정확한 Vercel URL** 기입 (`https://*.vercel.app` 무효) |
| F9 | Vercel 배포가 **`Blocked`** (prod 반영 안 됨) | 커밋 author가 Vercel 계정 소유자가 아님 → Hobby는 협업(외부 author) 커밋 배포 차단 ("commit author does not have contributing access") | 커밋 author를 **계정 소유자 이메일**로 맞춤. 로컬 `git config user.email`을 계정 등록/`@users.noreply.github.com` 이메일로 고정. 이미 쌓인 Blocked 커밋은 author 재작성 후 `git push --force-with-lease`. (**유료 전환 불필요**) |
| F10 | AI 분석 `Vision AI service unavailable` (502, `INVALID_ARGUMENT: Provided image is not valid`) | Vertex Vision에 **너무 작은/깨진 더미 이미지** 전달(예: 1×1 png) | 실제 사진급 유효 이미지 사용. 원인은 GCP 연동이 아니라 입력 이미지 — 정상 이미지면 200. 스모크 테스트 시 수백 KB급 JPEG 사용 |

## 3. 배포 절차 (순서 중요)

> 아래 `$RAILWAY_API_TOKEN` 등은 §1.3 값. 백엔드 명령은 `owner/surplus-hub-api-v3`에서 실행.

### 3.1 브랜치 준비
```bash
# 각 repo에서 배포 대상 브랜치 생성 (예: develop)
git branch develop main && git push -u origin develop
```

### 3.2 Cloudflare R2 (백엔드와 독립 — 먼저 해도 됨)
```bash
export CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=<계정ID> CI=true
wrangler r2 bucket create surplus-hub-uploads
# CORS는 wrangler 포맷({"rules":[...]}) — S3 배열 포맷과 다름!
cat > /tmp/r2-cors.json <<'JSON'
{ "rules": [ { "allowed": { "origins": ["https://<프론트도메인>","http://localhost:4000","http://localhost:3000"],
  "methods": ["GET","PUT","POST","HEAD"], "headers": ["*"] }, "exposeHeaders": ["ETag"], "maxAgeSeconds": 3600 } ] }
JSON
wrangler r2 bucket cors set surplus-hub-uploads --file /tmp/r2-cors.json
wrangler r2 bucket cors list surplus-hub-uploads
# 검증: boto3로 put/get/delete (아래 3.6의 R2 검증 스크립트)
```

### 3.3 Railway 백엔드 — GitHub 연결 (브라우저, 자동배포용)
1. `railway.com/new` → **Deploy from GitHub repo** → `surplus-hub-api-v3` (GitHub App 권한 허용)
2. 서비스 **Settings → Source → Branch = `develop`**
3. 프로젝트에 **`+ New → Database → PostgreSQL`** 추가 (서비스명 `Postgres` 유지 → `${{Postgres.DATABASE_URL}}` 참조)
4. 첫 자동 빌드는 env 없어서 **실패가 정상** (아래에서 채움)

### 3.4 pgvector 활성화 (env 주입 **전에**!)
```bash
export RAILWAY_API_TOKEN=...
railway link --project <프로젝트명>          # 서비스 자동선택
PGURL=$(railway variables -s Postgres --json | jq -r '.DATABASE_PUBLIC_URL')
python3 - <<PY   # (psycopg2 필요)
import os,psycopg2
c=psycopg2.connect("$PGURL"); c.autocommit=True
c.cursor().execute("CREATE EXTENSION IF NOT EXISTS vector")
print("pgvector ok")
PY
```
> Railway 기본 Postgres 이미지에 pgvector 포함됨(0.8.5) — Supabase 폴백 불필요.

### 3.5 백엔드 환경변수 주입 (재배포 트리거)
```bash
railway variables -s surplus-hub-api-v3 \
  --set 'APP_ENV=prod' \
  --set "SECRET_KEY=$(openssl rand -hex 32)" \
  --set 'ALGORITHM=HS256' \
  --set 'ACCESS_TOKEN_EXPIRE_MINUTES=60' \
  --set 'CORS_ORIGINS=["https://<프론트도메인>","http://localhost:4000","http://localhost:3000"]' \
  --set 'AI_PROVIDER=vertex' \
  --set 'GOOGLE_CLOUD_PROJECT=est-alan-451902' \
  --set 'GOOGLE_CLOUD_LOCATION=us-central1' \
  --set "AWS_ACCESS_KEY_ID=<R2키>" \
  --set "AWS_SECRET_ACCESS_KEY=<R2시크릿>" \
  --set 'AWS_S3_BUCKET_NAME=surplus-hub-uploads' \
  --set 'AWS_S3_REGION=auto' \
  --set "AWS_S3_ENDPOINT_URL=<R2엔드포인트>" \
  --set 'MAX_UPLOAD_SIZE_MB=10' \
  --set "GOOGLE_CLIENT_ID=<구글client id>" \
  --set 'WEB_CONCURRENCY=2' \
  --set 'FRONTEND_URL=https://<프론트도메인>' \
  --set 'DATABASE_URL=${{Postgres.DATABASE_URL}}'
# GCP SA는 값이 커서 별도로:
railway variables -s surplus-hub-api-v3 --set "GCP_SA_JSON=$(cat /경로/service-account.json)"
railway domain -s surplus-hub-api-v3      # 공개 도메인 발급
```
> 전체 키 목록·의미는 §5 표 참조. `CORS_ORIGINS`는 **정확한 프론트 URL**(와일드카드 X).

### 3.6 백엔드 검증
```bash
RAILWAY_URL=https://<백엔드도메인>
curl -s $RAILWAY_URL/health | jq .                      # {"status":"ok","checks":{"api":"ok","database":"ok"}}
curl -s "$RAILWAY_URL/api/v1/categories/" | jq '.data|length'   # 시드 카테고리 수
curl -s -X OPTIONS -H "Origin: https://<프론트도메인>" -H "Access-Control-Request-Method: GET" \
     -D - -o /dev/null "$RAILWAY_URL/api/v1/categories/" | grep -i access-control-allow-origin
```

### 3.7 Vercel 프론트 — GitHub 연결 (브라우저)
1. `vercel.com/new` → `surplus-hub-react` import
2. **Root Directory = `apps/web`** (모노레포 필수)
3. **Production Branch = `develop`** (Settings → Git)
4. Environment Variables:
   - `NEXT_PUBLIC_API_URL = https://<백엔드도메인>`
   - `NEXT_PUBLIC_GOOGLE_CLIENT_ID = <구글client id>`
5. Deploy → 배포 URL 확인

### 3.8 연동 마무리
- 백엔드 `CORS_ORIGINS`·`FRONTEND_URL`에 확정된 Vercel URL 반영(§3.5) → 자동 재배포
- Google Console OAuth → Authorized JS origins에 Vercel URL 추가 (구글 로그인용)

## 4. end-to-end 검증 (실제 통과 항목)

| 항목 | 방법 | 기대 |
|---|---|---|
| 회원가입 | `POST /api/v1/auth/register` `{name,email,password}` | 200 + accessToken/refreshToken |
| 내 정보 | `GET /api/v1/users/me` (Bearer) | 200 |
| UI 로그인 | `/sign-in` 폼 제출 | 홈 리다이렉트, 로그인 상태 |
| presign | `POST /api/v1/upload/presigned-url` `{filename,content_type}` (Bearer) | 200 (uploadUrl/publicUrl/key) |
| R2 업로드 | presign의 uploadUrl로 브라우저 PUT | 200, `<계정>.r2.cloudflarestorage.com` |
| RBAC | `GET /api/v1/admin/dashboard/summary` 무인증 | 401 |

> ⚠️ 업로드 경로는 `/upload/presigned-url` (presign 아님), 자재 이미지 직접 업로드는 `/upload/image`.

## 6. dev / stage 환경 추가 시 (권장 패턴)

목표: 브랜치별 환경 분리. 예) `develop`→dev, `stage`→staging, `main`→prod.

### 6.1 Railway
- **환경(Environment) 분리 권장**: Railway 프로젝트에서 `railway environment new staging` → 환경별 변수 세트.
  - 또는 서비스를 복제해 브랜치만 다르게 연결.
- 각 환경 서비스의 **Source Branch**를 해당 브랜치로. Postgres는 환경별로 별도 인스턴스 추가.
- 변수는 환경마다 `railway variables -e <env> -s <svc> --set ...`.

### 6.2 Vercel
- Vercel은 자동으로 **Preview 배포**(비-production 브랜치 push)를 만든다 → dev/stage는 Preview로 활용 가능.
- 명시적 stage가 필요하면 **별도 Vercel 프로젝트**를 stage 브랜치에 production으로 연결.
- 환경변수는 Vercel의 Production/Preview/Development 스코프로 분리 (`NEXT_PUBLIC_API_URL`을 각 백엔드로).

### 6.3 R2
- 환경별 버킷 분리 권장: `surplus-hub-uploads-dev`, `-stage`. 각 버킷 CORS에 해당 프론트 도메인 추가.

### 6.4 CORS / OAuth
- 각 환경 프론트 도메인을 **백엔드 `CORS_ORIGINS`** 와 **Google OAuth origins** 양쪽에 추가(정확 URL).

## 8. 코드에 반영된 배포 수정 (커밋됨)
- `docker-entrypoint.sh`: GCP SA → `/tmp/gcp.json` (비-root 안전)
- `railway.json`: `healthcheckTimeout: 300`, startCommand = entrypoint→gunicorn
- `gunicorn.conf.py`: `bind 0.0.0.0:$PORT`, `WEB_CONCURRENCY` 워커
- 이 수정들은 `main`·`develop` 양쪽에 있음.
